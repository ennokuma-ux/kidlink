Integration checklist

1. Confirm the actual Student model and column names in your project.
   This example assumes App\Models\Student and columns full_name, nickname, id.
   If your table uses fullname or another column, update the query and Blade output.

2. Confirm the teacher access rule.
   In the example controller, replace the TODO query and findOrFail() with your current teacher-to-student relationship/scope. Authorization must apply both to search results and the individual analytics route.

3. Add routes carefully.
   Merge routes/web.php.example into your existing routes/web.php; do not replace the whole file.
   The Blade form expects:
   - teacher.analytics.individual.index
   - teacher.analytics.individual.show

4. Include the search partial in your existing individual analytics Blade page:
   @include('teacher.analytics.partials.student-search', ['students' => $students ?? null])

5. Create/adapt the destination views:
   - resources/views/teacher/analytics/individual.blade.php
   - resources/views/teacher/analytics/individual-show.blade.php
   The example controller references these views; use your existing analytics views if you already have them.

6. Search for the age-group phrase “2–3 year olds” (also check "2-3 year olds", "2 to 3 year olds", and similar wording) and update the intended UI copy to “1–3 year olds”. Avoid changing unrelated educational logic without confirming the age-range rules.

7. Test:
   - Teacher can search by full name.
   - Teacher can search by nickname.
   - Empty results show a helpful message.
   - A teacher cannot open another teacher's student analytics by changing the URL.
   - Non-teachers receive 403/redirect according to your app's existing authorization design.
   - Existing analytics calculations still use the current KidLink implementation.
